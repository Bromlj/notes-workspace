## Test methods and limits

Playwright drove the application's own Electron instance. Native keyboard handling was tested with Electron input events; Chromium's synthetic key events do not exercise every native shortcut path. The renderer retained sandboxing, context isolation and disabled Node integration throughout.

Automated Save As/folder-picker/account-launch tests replaced those **main-process dialog/browser boundaries** with controlled test responses; they verified the resulting file writes, folder selection and official HTTPS sign-in launch without clicking physical Windows dialogs or opening a real OAuth page. Fresh human OAuth completion, first-time Windows administrator sandbox setup, every third-party integration and other computers were not tested. Existing sandbox readiness and real sandboxed commands passed on this host.

Codex CLI 0.162.0 was rejected for this release after a live command test exposed a Windows sandbox refresh failure involving an active desktop runtime. The pinned official 0.160.0 redistributable passed both a direct sandboxed command and the full packaged live edit/test workflow. Sandbox and approval protections were retained.

The application and installer are not custom code-signed. A launcher with modified icon/version resources was blocked by Device Guard on this machine; the unchanged official runtime passed the same launch and packaged checks. No Windows protection was disabled. Windows download reputation checks or managed policies can differ between PCs. These measured checks are not a guarantee of perfection or compatibility with future Codex/service changes.

## Data and privacy

Release construction copies explicit application/runtime/license files into a clean build directory. The ZIP builder checks for credentials, connection tokens, browser profiles, notes and application data, then verifies every ZIP entry's CRC and writes SHA-256 checksums. User data lives outside the program directory and is never a release input. Each recipient signs into their own account.

The cover provides visual privacy. It does not hide processes, history, authentication pages, native dialogs, screen recording or system inspection. Closing the entire program can interrupt work; hiding the Reference panel does not cancel accepted work. Notes and local backups are not encrypted.

Note editing is opt-in for each note/chat. Codex edits a private per-turn UTF-8 mirror, with only its exact directory added to the existing project sandbox for that turn. The mirror is removed on ordinary completion/stop/close; staged revision text remains in the local conversation store for reveal/conflict review. Hidden AI revisions never change the ordinary note's editor or canonical recovery text. Manual changes take priority until the user explicitly applies a revision. Undo AI edit turns editing off before restoring the whole pre-task snapshot; further AI updates from that run cannot overwrite it. Existing Codex threads are retained. As with ordinary editor undo, the live undo history is not retained across a full process restart.

Reproducible test scripts and detailed local results are retained in the source workspace under `tests/desktop-*.cjs` and `tests/desktop-*-results.json`. Test profiles and private local results are excluded from the shared app package.
