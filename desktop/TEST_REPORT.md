# Notes Workspace Desktop 5.2.0 verification

Verified on the development Windows x64 laptop on 9 October 2026. Tests launched the packaged **Notes Workspace.exe** with disposable application profiles, actual text files and project folders. The app bundles Electron 44.7.0 and the official Codex CLI 0.160.0 and runs independently of Edge. No separately installed Node or Python runtime is needed to use it.

- **4 first-run checks with an empty isolated Codex home.** Ordinary notes worked without credentials, the real CLI detected no sign-in, the Account page enabled official sign-in, and Alt+Q returned to plain notes. No prompt was submitted from the empty profile.

These comprise **101 packaged-app checks**, plus **152 helper tests**. The seven suites that record renderer exceptions reported zero. Live tests did not automatically approve additional-access requests.

The release has no custom code-signing certificate.

## Methods and limits

Playwright drove the app's own Electron instance. Native keyboard handling used Electron input events. The renderer retained sandboxing, context isolation and disabled Node integration. File/folder picker and account-launch tests substituted controlled responses at the main-process native-dialog/browser boundaries; they tested actual resulting writes and official HTTPS authentication launch without clicking physical Windows dialogs or completing fresh human OAuth.

Fresh human sign-in, first-time administrator sandbox setup, every proprietary Codex desktop integration and other computers were not fully tested. Real sandboxed project commands passed on this host. Codex CLI 0.162.0 had exposed a Windows sandbox refresh failure during earlier verification; this release retains the official 0.160.0 runtime that passed the live workflows. Sandbox and approval protections remain enabled. These measurements do not guarantee perfection or compatibility with future service changes or every managed Windows policy.

Release construction uses explicit application/runtime/license inputs. Packaging rejects private-data filenames, hashes every file, verifies every archived file against the manifest, and writes a ZIP SHA-256 checksum. Developer test profiles, credentials, notes, bindings and private results are not included. Each recipient uses their own account.

## Direct files and visual privacy

An opened note is a binding to a real UTF-8 file, not an import/export copy. Untitled notes use persistent app-local document files. The main process owns file bindings; backups do not grant access to original machine paths. For an opted-in note-edit turn, Codex receives the actual file path and its folder in addition to the selected project's normal access. The document remains after completion. Project tasks retain normal Codex tools, sandbox restrictions and approval prompts.

**Alt+Q freezes the visible note and its canonical recovery text, while actual disk edits continue.** Another program reading that file can see those changes. Reveal catches up unless manual edits require explicit review. Save and Undo refuse stale disk hashes. Undo AI edit waits for the task to finish and restores the real file plus the pre-task rich note; Undo history is not retained across a full process restart. Turning note editing off pauses UI updates but cannot revoke file access already granted to an active turn; Stop is the explicit cancellation control. Use Reload for external changes and Relink for moved/missing files instead of recreating an old path.

The cover provides visual privacy, not concealment from system inspection. It does not hide processes, recording, authentication pages or native dialogs. Closing the whole app, crashes, sleep or connection loss can interrupt work. Notes and backups are not encrypted.

Reproducible scripts are included under `tests/desktop-*.cjs`. Private local result files and disposable profiles are ignored by Git and excluded from the app release.
